# Проверка безопасности и оптимизации BYTE — 28.10.2026

## Итог

Исправления подготовлены в отдельной копии кода. Это внутренний обзор и автоматические регрессионные проверки, не независимый пентест и не гарантия отсутствия уязвимостей. Публичный выпуск не произведён: сервера/домена пока нет, Docker в проверочном окружении отсутствует.

## Найдено и исправлено

| Приоритет | Находка | Исправление |
|---|---|---|
| Критический | Python/C++ решения исполнялись рядом с сайтом без файловой/сетевой изоляции | Backend Docker по умолчанию; запрет local в production, ограниченные контейнеры для компиляции и запуска; сравнение скрытых ответов вне контейнеров |
| Высокий | DEBUG по умолчанию, известный dev-secret; .env загружался после чтения этих настроек | Ранняя загрузка .env, DEBUG=0, обязательный production secret, явные хосты, HTTPS/cookies/headers |
| Высокий | Контестный аккаунт с назначенным владельцем принимал другого авторизованного ученика при знании пароля | Проверка владельца при входе и каждом чтении сессии; смена session key |
| Средний | AI мог обращаться к закрытой по учебному прогрессу теме напрямую | Та же проверка доступа, что в материалах |
| Средний | Отсутствовали общие лимиты входа/заявок; лимит AI обходился гонкой | Атомарные счётчики в БД на вход, заявки и AI, Retry-After; HMAC-ключи; общий lease на обе разновидности отправок |
| Средний | Ошибка 500 на JSON-сообщении AI неправильного типа | Проверка типа и ответ 400 |
| Средний | Старое локальное окружение Python 3.9 / Django 4.2 | Проверенная связка Python 3.12.14 / Django 5.2.18; зафиксированы 31 runtime-зависимость |
| Средний | Не были подготовлены production static server, ограничение AI timeout, согласованный бэкап | WhiteNoise + manifest/compression, Gunicorn/nginx шаблоны, timeout SDK, SQLite backup API с проверкой и правами 0600 |

Дополнительно: no-store/private на авторизованных ответах, CSP для пользовательских страниц, заголовок Permissions-Policy, игнорирование резервных копий в Git. Заявки принимаются при явном согласии; блокировки по отсутствию ИИН не добавлялись.

## Проверки и ограничения доказательств

- 79 серверных тестов успешно выполнены на Django 5.2.18, включая прежние 65 и новые проверки прав, лимитов, CSRF, malformed JSON, личного кэша, закрытого AI-раздела, запрета host fallback, параметров контейнера и очистки при тайм-ауте.
- `manage.py check`, `makemigrations --check --dry-run`, `git diff --check` — успешно. Сборка статики — 144 файла и 432 результата обработки.
- `check --deploy` с production-настройками: только W005/W021 (HSTS на поддомены/preload отложены до выбора домена). В исходном состоянии было шесть предупреждений, включая DEBUG, слабый ключ и незащищённые cookies.
- `pip-audit` установленного проверочного окружения: известных уязвимостей не найдено после обновления pip до 26.2.2. Это снимок базы уязвимостей на дату проверки. Runtime lock фиксирует проверенные версии; отдельно проверить разрешение зависимостей на целевом Linux.
- Поиск высокодостоверных шаблонов API-ключей/приватных ключей в текущих отслеживаемых файлах: совпадений нет. История Git и реальные серверные секреты этим не аудировались.
- В браузере: CSP, переключение темы, cookie preferences, успешная синтетическая заявка с согласием и отказ без него, вход, приватные cache headers, урок, аналитика и мобильная шапка; ошибок JavaScript нет.
- Бэкап **синтетической** локальной SQLite БД создан через backup API; integrity_check=ok, копия читается, права 0600. Реальное восстановление production БД ещё не проверялось.
- **Docker не установлен.** `verify_judge` корректно останавливается с ошибкой об отсутствии Docker. Unit-тесты параметров контейнера не заменяют реальные тесты изоляции; до их выполнения запуск контестов на публичном сервере не одобряется.
- AI-провайдер, nginx/TLS, реальная инфраструктура, конкурентная нагрузка, доставка/обработка заявок оператором и восстановление реальной базы не проверялись.

## Производительность

Одинаковый Python 3.12/Django 5.2, локальный Django TestClient, 15 последовательных измерений после прогрева. Синтетические данные: 64 раздела с крупными текстами RU/KZ, 20 задач, 8 отправок с исходниками 32 КБ на задачу. Сравнение до/после на изолированных БД; реальные данные учеников не использованы.

| Страница | Запросы до → после | Медиана до → после |
|---|---:|---:|
| Кабинет | 6 → 6 | 8.54 → 3.61 мс |
| Урок | 6 → 7 | 8.27 → 3.11 мс |
| Контест | 64 → 7 | 25.91 → 14.61 мс |

Тексты невыбранных уроков больше не загружаются вместе с навигацией. Дополнительный запрос урока получает только выбранное содержимое. История контеста ограничена восемью отправками на задачу через оконную функцию, исходники не выбираются; результаты агрегируются общими запросами вместо запросов на каждую задачу.

Это измерение генерации страниц, не проверка пропускной способности production-сервера и не тест конкурентных Docker-запусков. Статика, сеть, HTTPS и реальные устройства дадут другие времена.
