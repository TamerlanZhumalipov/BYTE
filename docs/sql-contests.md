# SQL-контесты BYTE

SQL — отдельный тип контеста с тремя задачами. Python/C++ остаются в типе «Программирование». Язык отправки проверяется сервером; смешанного режима нет. Старые контесты миграция относит к программированию.

## Установка и первый контест

После обновления кода в активированном окружении проекта:

```bash
python manage.py migrate
python manage.py seed_sql_contest --starts-in 10 --minutes 40
python manage.py runserver
```

На сервере с собранной статикой также выполните `python manage.py collectstatic --noinput` и перезапустите приложение обычным способом.

Команда **создаёт новый** SQL-контест, не перезаписывая существующие. Повторный запуск создаёт ещё один контест. Она выводит случайный пароль демонстрационного участника; сохраните его. Ученик сначала входит в обычный кабинет BYTE, затем в «Лайв-контесте» выбирает **SQL** и вводит выданные куратором логин/пароль контеста.

Для остальных участников используйте существующую команду `create_contest_accounts` или админку. Назначайте аккаунт именно SQL-контесту; при необходимости свяжите его с учётной записью ученика для аналитики.

Первый комплект:

1. Рейтинг учеников — фильтрация по порогу и стабильная сортировка.
2. Сильные группы — COUNT, AVG, GROUP BY/HAVING, округление.
3. Лучший результат каждого — LEFT JOIN, MAX, COALESCE, ученики без попыток.

У каждой задачи открытые таблицы, пример результата и шесть скрытых наборов. Условия и названия доступны на RU/KZ. Наборы проверяют пустые таблицы, границы, NULL, повторяющиеся имена и сортировку. Успешный скрытый набор даёт один балл, максимум 6 за задачу и 18 за комплект. Пробные запуски не создают отправки и не влияют на баллы.

## Пользовательский интерфейс

- **Запустить запрос** выполняет запрос только на открытом наборе и показывает имена столбцов/строки. Это не проверка на совпадение с ответом и не начисление баллов.
- **Отправить решение** проверяет скрытые наборы, сохраняет вердикт, лучший результат и историю. Ctrl/⌘+Enter отправляет решение.
- Черновики сохраняются отдельно по контесту, участнику, задаче и языку.
- До начала и после завершения контеста оба действия запрещены сервером. Неверный тип аккаунта, чужая задача и неподходящий язык отклоняются.
- Одновременные SQL-запуски одного участника блокируются общей записью в БД; после завершения есть пауза 2 секунды. Для отправок действует прежняя пауза 10 секунд. Разные веб-процессы разделяют эту блокировку.

## Создание собственных задач

В админке «Контесты» выберите тип **SQL**, задайте расписание и ровно три задачи. Тип контеста с уже созданными задачами менять нельзя. У каждой SQL-задачи заполните:

- Условие, название и при необходимости казахские версии.
- Открытый набор `sql_sample`.
- Эталон `sql_reference` — остаётся на сервере.
- `sql_ordered`: включите, если в условии требуется порядок строк.
- Лимит времени: больше 0 и не больше 3 секунд.

Скрытые наборы добавляются на странице задачи через встроенный список тестов или через «Тесты». Для SQL заполняйте только `sql_fixture`, оставляя stdin/stdout пустыми. Нужен хотя бы один и не больше 10 наборов. У каждого набора должна быть та же схема, что у открытого; меняются только строки. Не включайте настоящие персональные данные.

Формат набора:

```json
{"tables": [{"name": "students", "columns": [["id", "INTEGER"], ["name", "TEXT"], ["score", "INTEGER"]], "rows": [[1, "Алия", 35], [2, "Тимур", null]]}]}
```

Поддерживаются типы INTEGER, REAL, TEXT, NUMERIC. В наборе 1–8 таблиц, до 32 столбцов и 1000 строк на таблицу, общий JSON до 512 КБ. Имена — латинские буквы/цифры/подчёркивание, начиная с буквы; `sqlite_` и `pragma_` зарезервированы. Внешние ключи и ограничения уникальности не создаются автоматически: автор набора отвечает за обещанные в условии инварианты.

SQL-диалект — **SQLite**, не PostgreSQL/MySQL. Разрешены чтение, CTE, соединения, агрегаты и ограниченный список функций из `core/sql_engine.py`. Служебные таблицы, PRAGMA, подключение файлов, изменения схемы/данных и расширения запрещены.

Сравнение результатов:

- Сравниваются значения и порядок столбцов; названия/алиасы столбцов не влияют на оценку.
- Повторяющиеся строки учитываются по количеству.
- Порядок строк учитывается только при `sql_ordered=True`.
- NULL отличается от пустой строки и нуля. Числовые 1 и 1.0 равны, строка "1" отличается.
- Числа сравниваются точно, без приблизительного допуска. Если нужно округление, укажите точность и ROUND в условии.
- Результат ограничен 2000 строками и 512 КБ. Эталон тоже обязан укладываться в лимиты.

## Проверяющая среда

Запрос не передаётся Django ORM или соединению с базой BYTE. Каждый набор проверяется отдельным Python-процессом, который запускает только доверенный `sql_engine.py`, создаёт SQLite `:memory:` из ограниченного JSON и не получает ключи/окружение Django. Идентификаторы проверяются, значения вставляются параметризованно. Эталон и решение получают независимые свежие соединения.

Защита: authorizer с разрешёнными операциями/функциями, query_only, отключённые расширения, temp_store=MEMORY, лимит SQLite heap 64 МиБ, ограничение SQL 64 КиБ, ограничения результата, progress handler, тайм-аут родительского процесса, общий бюджет отправки 20 секунд. На поддерживаемых Python дополнительно применяются `setlimit`; на Unix — CPU/file limits и Linux address-space limit. На Python 3.9 `setlimit` отсутствует, поэтому остаются остальные слои.

Это ограниченный SQL-процесс, **не контейнерная/OS-песочница**. Обновляйте Python/SQLite, ограничивайте общую конкурентность веб-воркеров и ресурсы сервиса. На массовом публичном запуске разумно вынести проверяющий процесс в отдельный непривилегированный сервис/контейнер. Существующий Python/C++ judge этим изменением не переделывается.

Скрытые строки и эталон не отправляются в HTML/JSON страницы. Ошибки на скрытых наборах возвращаются без SQLite-деталей, которые могли бы зависеть от содержимого. Открытый запуск показывает ошибку SQLite только для открытого набора.

Обоснование защиты: [рекомендации SQLite для недоверенных запросов](https://www.sqlite.org/security.html), [Python sqlite3: authorizer, progress handler и execute](https://docs.python.org/3/library/sqlite3.html).
