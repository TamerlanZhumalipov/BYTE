# BYTE — кабинет ученика

Python 3.10+ и Django 4.2–5.x. Проект курса информатики: материалы, прогресс, учебные тесты с разбором,
лайв-контесты и BYTE AI. Светлая/тёмная тема применяется к лендингу, входу,
кабинету и чату. Начальная тема следует системе, выбор сохраняется в браузере.

## Локальный запуск / обновление

Из папки проекта, в своём виртуальном окружении:

```bash
python -m pip install -r requirements.txt
python manage.py migrate
python manage.py runserver
```

Перед миграцией существующего сайта сохраните резервную копию БД. Миграция
`0002` добавляет таблицы, не изменяя существующие материалы и контесты.
Откройте http://127.0.0.1:8000/ . Для админки создайте пользователя командой
`python manage.py createsuperuser`. Ученики используют стандартные Django-аккаунты;
существующая команда `create_student` продолжает работать.

Для нового проекта при необходимости:

```bash
python manage.py seed_materials
python manage.py seed_quizzes --publish
```

`seed_quizzes` добавляет три теста по пять вопросов (Python, системы счисления,
логика). Без `--publish` они создаются черновиками. Повторный запуск не изменяет
существующие тесты. Тесты и вопросы редактируются в `/admin/` → «Учебные тесты».
В этой версии каждый вопрос имеет четыре варианта и один правильный ответ.

## Обучение

- «Изучено» хранится в БД отдельно для каждого ученика; отметку можно отменить.
- В прогресс входят опубликованные разделы с непустым содержимым, доступные
  через дерево материалов. Пустые разделы и скрытые ветки не учитываются.
- Кнопка продолжения ведёт к последнему открытому незавершённому уроку,
  либо к первому незавершённому уроку по порядку курса.
- Баллы тестов вычисляет сервер. Все вопросы обязательны. Повторная отправка
  одной формы не создаёт вторую попытку. Новый запуск теста — новая попытка.
- История сохраняет вопросы, варианты и объяснения на момент проверки, поэтому
  последующие изменения и удаление теста не меняют старый разбор.
- Средний результат — среднее процентов всех попыток, а не только лучших.
- Учебные тесты и результаты контестов — отдельные сущности.

## BYTE AI

Скопируйте `.env.example` в `.env`, заполните `GEMINI_API_KEY` и при необходимости
`GEMINI_MODEL` доступной моделью из Google AI Studio. Перезапустите сервер.
Без ключа кабинет работает; чат показывает сообщение о неподключённом сервисе.
Стоимость и лимиты определяет Google, бесплатный доступ не гарантируется.

SDK: https://googleapis.github.io/python-genai/

Чат использует историю текущей Django-сессии (последние 12 сообщений) и текст
открытого опубликованного урока (до 6000 символов). История доступна между
страницами до очистки чата, выхода из аккаунта или истечения сессии. Внешнему
сервису передаются вопрос, недавний диалог и контекст урока, без паролей и баллов.

Ключ хранится только на сервере. Предусмотрены ограничения длины, тайм-аут
провайдера 30 секунд, защита от параллельной отправки и интервал 5 секунд между
вопросами. Ошибки провайдера не раскрываются в браузере. На нескольких процессах
сервера настройте общий Django cache (например, Redis), чтобы ограничения
действовали между процессами. Текущий локальный cache действует в одном процессе.

Текст и код ответа выводятся безопасно через DOM `textContent`; блоки кода можно
копировать. Плавное появление ответа — клиентская анимация после получения
полного ответа, не потоковая передача от провайдера.

## Проверки

```bash
python manage.py check
python manage.py test core
python manage.py makemigrations --check --dry-run
```

Тесты проверяют разграничение доступа, прогресс, серверную оценку, повторную
отправку, неизменность истории и обработку AI-ошибок. Внешние AI-запросы в
автотестах заменены заглушкой; реальную интеграцию проверяйте своим ключом.
