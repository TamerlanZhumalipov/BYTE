# BYTE — сайт курса подготовки к ЕНТ по информатике

Django-сайт: лендинг с заявками, закрытый кабинет ученика (16 тем материалов с подразделами)
и лайв-кодинг контест (отдельный вход, таймер, 3 задачи × 100 тестов).

Аккаунты учеников **не создаются самостоятельно**: куратор выдаёт логин и пароль вручную.

---

## 1. Установка с нуля (macOS)

Нужен только Python 3 (проверьте: `python3 --version`).

```bash
cd ~/Desktop
unzip ~/Downloads/byte-project.zip        # появится папка byte_site
cd byte_site
bash setup.sh                             # окружение, Django, таблицы, 16 тем
```

Затем:

```bash
source venv/bin/activate                  # включить окружение
python manage.py createsuperuser          # администратор для /admin/
python manage.py seed_demo_contest        # демо-контест (печатает логин и пароль участника)
python manage.py runserver                # сайт: http://127.0.0.1:8000/
```

**Каждый раз в новом окне терминала:**

```bash
cd ~/Desktop/byte_site
source venv/bin/activate
```
Без `(venv)` в начале строки команды `python manage.py ...` не работают.

### Сразу включите Git

```bash
git init
git add .
git commit -m "Первая версия BYTE"
```
Создайте приватный репозиторий на github.com и выполните две команды, которые он покажет
(`git remote add origin ...` и `git push -u origin main`). Дальше после каждого рабочего изменения:

```bash
git add .
git commit -m "что сделал"
git push
```
Файл `db.sqlite3` в Git не попадает (там пользователи и результаты) — копируйте его отдельно.

### Таблицы базы данных (core/models.py)

| Модель | Что хранит |
|---|---|
| `Lead` | заявки с лендинга: имя, телефон, пакет |
| `Section` | материалы: тема или подраздел (поле `parent`), порядок, HTML-текст |
| `Contest` | контест: название, начало, длительность в минутах |
| `ContestTask` | задача контеста: номер, условие, лимит времени на тест |
| `TaskTest` | один тест: входные данные и правильный ответ (100 на задачу) |
| `ContestAccount` | отдельные логин и пароль участника контеста (пароль хранится в виде хеша) |
| `Submission` | отправка решения: код, язык, вердикт, пройдено тестов, результат по каждому тесту |
| `AIMessage` | история диалога ученика с ИИ-помощником: кто написал, раздел, текст, завершён ли диалог |

Ученики сайта — это стандартная таблица пользователей Django (`User`), отдельно от `ContestAccount`.

### Адреса (URL)

| Адрес | Что открывает | Доступ |
|---|---|---|
| `/` | лендинг | все |
| `/api/leads/` | приём заявки (POST) | все |
| `/login/`, `/logout/` | вход и выход (выход только кнопкой-формой) | все |
| `/app/` | кабинет: стартовая со списком тем | после входа |
| `/app/materials/<slug>/` | раздел материалов | после входа |
| `/contest/login/` | вход в контест по отдельному логину/паролю | после входа на сайт |
| `/contest/` | страница контеста | вход на сайт + вход в контест |
| `/contest/submit/` | приём решения (POST, JSON) | вход на сайт + вход в контест |
| `/app/materials/<slug>/ai/ask/` | вопрос ИИ-помощнику по разделу (POST, JSON) | после входа |
| `/app/materials/<slug>/ai/reset/` | начать новый диалог с помощником (POST) | после входа |
| `/admin/` | админка куратора | суперпользователь |

### Как это работает

**Путь ученика:** куратор выдаёт логин/пароль → `/login/` → кабинет `/app/` (материалы) →
вкладка «Лайв-контест» → `/contest/login/` (логин и пароль контеста) → `/contest/`.

**Состояния контеста** определяются по времени: до начала — обратный отсчёт и автообновление,
во время — 3 задачи, редактор и таймер, после конца — отправка закрыта, результаты сохранены.

**Проверка решения** (`core/judge.py`):
```
редактор → POST /contest/submit/ → проверки (время контеста, лимит частоты, размер кода)
        → judge.run_submission: создаёт временную папку, компилирует (C++) или проверяет синтаксис (Python)
        → запускает код на каждом из 100 тестов (лимит времени, памяти, размера вывода)
        → сравнивает вывод с ответом (пробелы в конце строк не важны)
        → Submission сохраняется, страница рисует сетку 10×10 и вердикт
```
Вердикты: OK (принято), WA (неверный ответ), TLE (время), RE (ошибка выполнения), CE (ошибка компиляции).
Балл за задачу — лучший результат среди всех отправок (сколько тестов из 100 пройдено).

## 3. Что нужно сделать перед первым реальным запуском

1. `python manage.py createsuperuser` — администратор.
2. В админке (`/admin/` → «Материалы») наполнить темы текстом. Структура из 16 тем уже создана командой `seed_materials`;
   названия и порядок можно менять, подразделы добавлять (поле «Родительский раздел»).
   Список тем — предложенный, сверьте его с актуальной спецификацией ЕНТ.
3. Создать реальный контест (см. раздел 4).

## 4. Ежедневная работа куратора

### Выдать доступ ученику (логин и пароль для сайта)
```bash
python manage.py create_student ivan_petrov --email ivan@mail.kz
```
Команда напечатает логин и случайный пароль — отправьте ученику. Свой пароль: `--password МойПароль123`.
Можно и через `/admin/` → «Пользователи» → «Добавить».

### Создать контест
`/admin/` → «Контесты» → «Добавить»: название, время начала, длительность. Прямо на той же странице
добавьте 3 задачи: номер, название, лимит времени, условие (HTML). В условии можно использовать блок примера:
```html
<div class="ex"><div><strong>Ввод</strong><pre>3 4</pre></div><div><strong>Вывод</strong><pre>7</pre></div></div>
```
Узнать ID контеста и задач: они видны в адресной строке админки (`.../contest/1/change/`).

### Загрузить 100 тестов к задаче
Подготовьте папку с парами файлов `01.in` / `01.out`, `02.in` / `02.out` … `100.in` / `100.out`
(`.in` — входные данные, `.out` — правильный ответ), затем:
```bash
python manage.py import_tests 3 ./tests/task3 --replace
```
где `3` — ID задачи. `--replace` удаляет прежние тесты этой задачи.

### Выдать участникам логины и пароли контеста
```bash
python manage.py create_contest_accounts 1 "Иван Петров" "Айгерим С." "Данияр К."
```
где `1` — ID контеста. Команда напечатает таблицу «имя — логин — пароль». Пароли показываются один раз.
Отдельного участника можно добавить или отключить в админке («Участники контеста»).

### Посмотреть результаты
`/admin/` → «Отправки»: кто, какая задача, вердикт, сколько тестов пройдено, код решения.
Фильтры справа — по контесту, задаче, вердикту.

### Заявки с сайта
`/admin/` → «Заявки».

## 4.1. ИИ-помощник по материалам

На странице каждого раздела материалов есть плавающая кнопка «Спросить помощника» (`core/ai.py`).
Помощник видит текст текущего раздела и последние реплики диалога, отвечает в духе репетитора:
объясняет идею и подсказывает, а не сразу выдаёт готовые решения задач. Работает через
**бесплатный уровень Google Gemini API** — банковская карта не нужна, только Google-аккаунт.
История диалога хранится в базе (`AIMessage`) и видна куратору в `/admin/` → «Диалоги с помощником» —
ученик её не удаляет, кнопка «Новый диалог» только скрывает переписку от самого ученика.

### Включение

1. Получите ключ на [aistudio.google.com/apikey](https://aistudio.google.com/apikey) — войдите под
   Google-аккаунтом и нажмите «Create API key». Бесплатно, без карты.
2. В корне проекта (рядом с `manage.py`) создайте файл `.env` на основе `.env.example`:
   ```bash
   cp .env.example .env
   ```
3. Впишите в `.env` свой ключ:
   ```
   GEMINI_API_KEY=...
   ```
4. Установите библиотеку (если ставили зависимости до этого раздела — обновите):
   ```bash
   pip install -r requirements.txt
   ```
5. Перезапустите `python manage.py runserver`. Кнопка помощника появится на странице раздела автоматически.

Если ключ не задан или библиотека не установлена, кнопка на сайте просто не показывается — сайт
продолжает работать без помощника.

### Настройки в `.env`

| Переменная | Что делает |
|---|---|
| `GEMINI_API_KEY` | ключ доступа к Gemini API. Без него помощник выключен |
| `AI_ENABLED` | `1` включает, `0` выключает помощника независимо от ключа |
| `AI_MODEL` | модель Gemini. По умолчанию `gemini-2.5-flash-lite` — лёгкая модель бесплатного уровня. Можно попробовать `gemini-2.5-flash` для чуть более качественных ответов, но у неё ниже бесплатные лимиты |

### Бесплатный тариф, лимиты и о чём стоит знать

Бесплатный уровень Gemini не требует карты и не выставляет счёт, но не безлимитен: у него есть
дневной лимит запросов и ограничение запросов в минуту — оба зависят от модели и меняются со стороны
Google, поэтому точные цифры смотрите на [ai.google.dev/gemini-api/docs/rate-limits](https://ai.google.dev/gemini-api/docs/rate-limits),
а не в этом файле. Если лимит исчерпан, Gemini вернёт ошибку, и ученик увидит сообщение «не получилось
получить ответ» — в этом случае помощник просто ждёт следующего дня или обновления лимита. Отдельная
защита от резких всплесков есть и на нашей стороне (`byte_project/settings.py`): не чаще одного вопроса
в 4 секунды и не больше 200 вопросов в сутки на одного ученика (`AI_COOLDOWN_SECONDS`, `AI_DAILY_LIMIT`).

**Важная оговорка про бесплатный тариф**: по условиям Google, запросы через бесплатный уровень API
могут использоваться для улучшения их моделей (в отличие от платного тарифа, где это отключено).
Для учебных вопросов по информатике это обычно не критично, но не отправляйте через помощника
персональные данные учеников или что-то чувствительное. Если это важно, переходите на платный тариф
Gemini (там за реальное использование школьного помощника счета выходят на копейки) — для этого
единственное, что нужно сделать, это привязать биллинг в Google Cloud Console к тому же проекту,
код менять не придётся.

### Безопасность

- Ключ читается только на сервере из `.env`, который не входит в Git (`.gitignore` уже настроен),
  и никогда не передаётся в браузер.
- Помощнику явно запрещено выдавать готовые решения задач контеста без попытки ученика и придумывать
  факты про формат ЕНТ — эти правила заданы в системной инструкции (`core/ai.py`, `SYSTEM_PROMPT`).
  Тем не менее ИИ может ошибаться; относитесь к ответам как к черновой подсказке, а не как к
  проверенному учебнику.

## 5. Частые ошибки

| Симптом | Причина и решение |
|---|---|
| `command not found: django-admin` / `No module named 'django'` | не включено окружение. Выполните `source venv/bin/activate` |
| `ModuleNotFoundError: No module named 'byte_project...'` | команда запущена не из папки, где лежит `manage.py`. Сделайте `cd ~/Desktop/byte_site` |
| Сайт открывается без стилей | папка `static/` должна лежать рядом с `manage.py`; проверьте `ls static/css` |
| `TemplateDoesNotExist` | папка `templates/` должна лежать рядом с `manage.py` |
| `no such table: core_...` | не применены миграции: `python manage.py makemigrations core && python manage.py migrate` |
| Кнопка помощника не появляется | нет `.env` с `GEMINI_API_KEY`, либо не установлен пакет `google-genai` (`pip install -r requirements.txt`) |
| В контесте «На сервере не найден компилятор g++» | на Mac выполните `xcode-select --install` |
| Ошибка при выходе (405) | выход работает только кнопкой в шапке (POST), а не ссылкой |

## 6. Ограничения и что делать перед публикацией в интернет

- **Проверка кода не изолирована.** Программы учеников запускаются на той же машине, что и сайт.
  Есть лимиты времени, памяти и вывода, но программа может читать файлы сервера. Для небольшой группы
  знакомых учеников на старте это допустимо; перед публичным запуском вынесите проверку в Docker или Judge0
  (заменяется одна функция — `run_submission` в `core/judge.py`).
- **Проверка идёт во время запроса** (до ~25 секунд на отправку). Для десятков одновременных участников
  понадобится очередь задач (Celery).
- **Продакшен:** задать `DJANGO_SECRET_KEY`, `DJANGO_DEBUG=0`, `DJANGO_ALLOWED_HOSTS`, включить HTTPS,
  собрать статику (`python manage.py collectstatic`), запускать через gunicorn + nginx, перейти на PostgreSQL.
- Нет: таблицы лидеров, отметок «прочитано» в материалах, оплаты. Это следующие шаги.
